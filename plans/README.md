## Backlog — worth doing, deliberately not planned this round

- **Country selector consolidation**: `CountryCombobox` in
  `apps/yachting/app/imhs-2026/onboard/page.tsx:112-207` and `CountryCombo`
  in `apps/yachting/app/admin/_components/ManualLeadForm.tsx:52-127` are two
  divergent implementations of the same autocomplete (different prop APIs,
  duplicated diacritic-folding). M effort, MED risk; do after 004.
- **Error/success state visual unification**: public forms use coral alert
  cards, admin uses red, `imhs-2026/onboard` uses bare red text; success
  panels are copy-pasted across 3+ forms. Needs a design decision (coral vs
  red is arguably intentional public-vs-admin language) before an executor
  plan is honest. Plan 004 adds `role="alert"` to all of them without
  changing visuals.
- **Button/CTA consolidation**: the shared `Button` is used on roughly half
  the CTA sites; the rest hand-roll `<a>`/`<button>` with drifting padding
  (`py-2` vs `py-2.5`) and radii. Worth consolidating, but each site needs a
  visual judgment call — do as a design-led pass with screenshots, not a
  cold-executor plan.
- **Spacing/radius/typography scale documentation**: section paddings
  (`py-16/24/32`), radii (`rounded-xl/2xl/3xl`), and per-page heading-size
  overrides of the global `clamp()` scale drift across pages. The fix is a
  documented scale + sweep, which risks visual regressions without design QA.
  Recommend the maintainer pick the scale first.
- **Inline rgba() gradient tokenization**: 6 inline gradients hardcode brand
  colors (`apps/yachting/app/adventure-yachts/page.tsx:694,720`,
  `[slug]/AdventureYachtDetail.tsx:232-233,596,622`). Low impact; fold into
  any future pass that touches those pages.

## Findings considered and rejected

- **Remove `force-dynamic` from `app/layout.tsx:10`** (would re-enable static
  rendering): the workaround exists because the app runs Clerk **v4**
  (`@clerk/nextjs ^4.29.1`) against Next 15; safely removing it means a Clerk
  v4→v6 upgrade — an infra/dependency project, not a UI change. Out of this
  audit's scope; worth its own initiative.
- **Header/Footer "duplication"** (`components/Header.tsx` vs ui
  `Navigation`, `components/SiteFooter.tsx` vs ui `Footer`): false positive —
  both app components are thin config wrappers around the shared components.
  Working as intended.
- **`.btn-ghost` reported as dead CSS**: false — used via the `ghost` variant
  in `packages/ui/components/Button.tsx:21`.
- **Reduce glassmorphism `backdrop-blur` (20px) for GPU perf**: the blur IS
  the brand aesthetic (28 usages); changing radius/coverage alters the visual
  design, which violates this audit's "without affecting usability/visuals"
  constraint. Revisit only with design sign-off and device profiling.
- **Tailwind `content` glob double-scanning** between the two configs:
  harmless build-time redundancy, negligible payoff.
- **Defer Microsoft Clarity init** (`components/Analytics.tsx`): micro-win on
  TBT; not worth a plan.
- **Extract duplicated Framer Motion variant objects** to a shared module:
  ~bytes-level win; pure churn.
- **A11y fixes inside WorldPremierePopup/MOTYVotePopup**: moot — components
  are dead code and plan 001 deletes them.
